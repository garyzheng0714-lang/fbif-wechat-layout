## Why

公众号 URL 导入的「章节小标题识别」被反复打补丁仍反复出错。最新病样
`mp.weixin.qq.com/s/nGe2BIRRWeItV1p3O6wxOQ`：「02 四大品牌差异化竞争策略拆解」
被降级成正文，而形态完全相同的「01 新鲜零食四强品牌共性特征」正常识别为标题。
根因不是判据不够多，而是历次修复都往识别条件里叠加**某一篇样例文章的巧合属性**
（有没有 `<b>` 标签、有没有冒号），把识别框越描越窄，换一篇没这些巧合属性的真标题
就漏判。这是典型的过拟合式创可贴——用户已明确要求「根治，不要治标不治本」。

## What Changes

- **归一识别判据**：微信章节小标题的识别不再依赖「run 全部落在 `<b>` 下」或「文本含冒号」
  这两个不可靠信号；改用微信排版的第一性信号——**字号相对正文放大（≥18px，正文恒 15–17px）
  + 居中 + 短（≤40 字）+ 非图片来源行/参考来源头/灰色或小字图注**。加粗与冒号降级为
  「有则更好、无也不影响」的非必要信号。
- **删除过拟合负向测试**：`TestCenteredLargeWithoutBoldTagIsNotHeadingNorCaption` 用一句
  编造字符串断言「居中大字无加粗 ⇒ 不是标题」，这个边界没有任何真实文章支撑，且正是它挡住了
  02 标题。改写为以真实病样 02 标题为回归守护的正向测试。
- **建立回归样例语料 + 修复协议**：把历次病样 URL 固化为共享 fixture；新增/修改标题判据时
  必须一次性跑通全部历史样例，且负向测试只能来自真实文章而非臆想。（防再犯的过程护栏。）

## Capabilities

### New Capabilities
- `wechat-heading-detection`: 公众号 URL 导入时，把正文块分类为「章节小标题 / 图注 / 正文」的
  判定规则——本次把小标题判据收敛到第一性信号，并锁定「不得依赖单篇样例巧合属性」这一原则。
