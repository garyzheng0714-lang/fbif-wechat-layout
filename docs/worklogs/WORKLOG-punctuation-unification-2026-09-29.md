## 编码前的失效清单

- 网站私有转换遗漏共享规则修复，网站和公众号再次产生不同序号。
- `...` 或括号空格转换改变长度，逐 run 回退丢失序号、引号上下文；等长但位置改变也可能错配粗体。
- 数字、URL、英文缩写横跨 run 后损坏；链接可见文字被跳过造成假序号；图片两侧被拼成一个数字或 URL。
- `br` 和段落边界被忽略，序号或引号沿用上一行/段状态。
- 网站 Markdown、DOCX、剪贴板在解析时先套用默认规则，网站参数不能恢复原文。
- 网站表格、商务行逐 run 转换，仍绕过段级上下文。
- 网站省略号被逐字符转换成 `。.。`，英文括号出现半角/全角混配。
- 合并误改公众号既有引号、英文片段、小数、括号及代码/URL保护；改变链接地址或字体属性。
- 浏览器与 render-service 实际加载不同实现，交互正确但自动发布仍错。

## 设计决定

L1 `punctuation.js` 提供唯一转换管线，只接收行为参数，不认识渠道名。网站模板显式声明参数，并传给解析入口；默认参数维持公众号/系列口径。按原文归属映射转换结果回各 run，删除按输出长度猜测边界和逐 run 回退。链接文案只读参与上下文，图片隔开相邻文字，换行保留结构。

网站保留相邻中文判定、原始引号/省略号/破折号与括号间距。明确纠正：完整省略号受保护、括号成对判断、技术片段保护和跨 run 上下文。网站英文括号成对保留半角，含中文的成对全角；只有当前段内完整的括号对参与转换，孤立/跨段 ASCII 括号保持原文。若一个括号在只读链接文字中，另一侧跟随它的形态。连续标点组一次到达最终状态，重复解析/渲染不得继续改变文字。

解析默认调用不变；网站通过模板 `punctuation` 属性将显式参数传给 DOCX、Markdown 与剪贴板入口。网站在元素/单元格完整上下文中统一转换，再做逐 run 视觉输出；包括提示声明的 `rest_runs`。标题编号的括号样式属于渲染层，保留现有规则。模块加载沿用 `assetQuery`，防止新旧缓存混用。

`punctuation.js` 负责共享转换和原文坐标映射，`punctuation-context.js` 负责中立上下文识别；删除网站私有转换器及按长度推算 run 边界的回退。URL、代码、HTML 标签与邮箱用原文范围保护，无占位符碰撞；缩短的标点 token 归属首字符所在 run，后续文字的字体/链接归属不变。

测试先写浏览器 E2E；继续运行现有 Node/Go/监控契约，不补写事后单元测试。`templates/fbif.js` 必须字节不动。
