## 当时目标（已被 2026-07-15 口径修正）

1. 用微信公众号**官方**接口 `freepublish/batchget`（合法正门，非爬 HTML）把
   `FBIF食品饮料创新` 订阅号（AppID/密钥见密钥文档，环境变量注入）的该端点响应
   原样归档，落成一个**可查询、可去重、可断点续抓**的端点快照库。它不能单独验收历史全量。
2. 每篇建查询索引：`article_id / 标题 / 作者 / 摘要 / 正文HTML / 封面 / 原文链接 /
   父对象 update_time（非已核验发布时间）/ news_item JSON`；完整端点页响应另行留档。
3. 从新到旧分页，**可限速、可断点续传**（分批执行并从上次游标继续），尊重微信每日配额。
4. 批量操作带**端点内分页计数校验**；`total_count` 只用于核对该次接口分页，不能解释为历史文章总量。

## 关键事实 / 决策

- **能抓**：2026-07-12 在排版服务正式环境实测，`cgi-bin/token` 返回
  `40164 invalid ip ..., not in whitelist`。
  这个错误码只在 **AppID/AppSecret 校验通过之后**才出现 → **凭据有效、接口可用**，
  唯一门槛是 IP 白名单。
- **当时唯一阻塞（用户动作）**：需在公众号后台把排版服务的生产出口 IP 加进「IP 白名单」。
  只有用户能操作，Claude 不代做。加完即可跑通。
- **服务器归属**：该出口来自发布流水线所在的正式环境，白名单加一个
  IP 同时解锁「历史补抓」和「未来新文章自动监控」（后者本质就是定时轮询同一个接口）。
- **token 共存风险**：微信 access_token 按 appid 全局唯一。若 FoodTalks 后端已在用同一
  appid，独立拉 token 会互相顶掉。**对策：用 `cgi-bin/stable_token`（force_refresh=false，
  可共存版）**，不清掉别人的 token。仍建议向后端确认该 appid 是否有其它系统在用。
- **库反查不出微信链接**：mc-fb 的 `news_news` 无任何 url 字段，`content` 是 FoodTalks
  加工版；所以必须走官方接口重抓，才能建原始文章库。
- **抓取范围**：用户裁定「先只抓这一个号」。其它 FBIF 子号（论坛/食品创新展/短视频…）
  各是独立公众号、各需自己的 AppID/密钥，以后逐个给、同一套代码复用。
- **存储选型**：Python3 + 内置 sqlite3，零第三方依赖（api 服务本身不用 sqlite，走 JSON
  文件存储，故不污染其构建）。库文件 `.db` 可查询、可导入 MySQL。
- **端点选型**：`freepublish/batchget` 返回“发布”对象，update_time 新→旧，但不覆盖后台“群发”；
  `material/batchget_material` 是素材库，不等于已发布。两者都应保留原始响应，但都不能单独或相加充当历史全量。
  注意：一个 `item`（article_id）可能是多图文，含多条 `news_item`，逐条入库，主键 (article_id, idx)。

## 当前覆盖结论

- 历史总量：**未完成 / 未核验**。任何年份都不能仅凭当前表的密度标成“接近全量”。
- `freepublish`：只代表该接口返回的“发布”对象；后台“群发”是另一条覆盖路径，必须独立持久化和关联。
- `material`：只代表素材库；`update_time` 还可能是素材迁移或编辑时间，不能当作真实发布日期。
- 当前 SQLite 主键和单表合并不足以完成多源稳定身份审计。需要保留各官方响应原貌，再按
  `msgid`、`msg_data_id`、文章序号、`article_id` / URL、发布日期等字段建立关联与冲突报告。
- 图片、图文、视频、语音素材库不纳入“已发布历史全量”自动同步；飞书多维表格同步保持关闭。

## 踩坑记录：offset 翻页竞态

列表实时变，新文章插 offset 0 会把后面挤下一位；断点按 next_offset 续抓会漏最新篇。
**结论**：单个端点完成一轮分页后可再跑一次 `--reset` 兜底；这只能说明补扫该端点，不能叫“全量抓完”。
日常增量从 offset 0 扫 + id 差集；跨来源仍需独立幂等与关联。

## 长期建议（非阻塞）

- 库建在当时已进白名单的独立归档服务。已发布监控可以独立轮询 `freepublish` offset 0 差集，但这只覆盖
  “发布”路径，不能代替“群发”发现；任何 `draft` / 素材接口失败都不得阻断已发布轮询。
- 若想抓取+监控与流水线**同机**运行，需把该环境的真实出口 IP 加入白名单；地址只在秘密配置中维护。
- 向 FoodTalks 后端确认 appid `wx72d6...` 的 token 占用（本工具用 stable_token 已规避冲突）。
- 已删除文章（`is_deleted`）：入库但打标，不当有效内容。
