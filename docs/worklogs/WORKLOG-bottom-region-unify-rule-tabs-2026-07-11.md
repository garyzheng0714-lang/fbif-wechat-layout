# WORKLOG：底部区域架构修正——规则=分段切换，署名图并入底部模块列表（2026-07-11）

## 用户批评（架构级，必须正视）

上一轮我把作者规则做成了独立的「文章专属设置」框 + 下拉，还把「参考文献前署名图」
命名为「文中元素」单拎出来。用户裁定：**这从架构上就错了**。

正确心智（用户原话拆解）：
1. 规则选择应是「好切换的动作」，不是藏起来的单选下拉。
2. 选规则 = 决定底部区域各模块的默认开关（不是一个孤立选项）。
3. 「参考文献前署名图」**属于底部区域**，不该叫「文中元素」/「文章专属设置」。
4. 选不同规则 → 底部区域显示不同模块 / 不同默认开关：
   - 默认规则：不显示「参考文献前署名图」（或默认关）
   - Mote 作者规则：默认打开

## 根因诊断（读代码确认）

底层**两套并行可见性机制**是割裂的根源：
- `block_visibility`（profile 配）→ 控制 bottom_blocks 的 block（提示/名片/更多文章）——统一模型
- `artifact_visibility`（profile 配）→ 控制 mote 署名图（behavior action `insert_image_before`
  `first_ref_heading`，渲染在正文参考文献前）——我把它做成了独立「文中元素」

两者本该在**面板交互层统一**为「底部区域的模块开关，规则决定默认」。

## 方案（纯 L4 交互层重组，不碰 L1/L2/L3）

关键判断：**渲染层和数据层都不用动**。
- 署名图仍由 behavior action 注入正文参考文献前（渲染位置不变）
- profile 的 artifact_visibility / block_visibility 数据不变
- 只重排 `block-panel.js` 的 DOM：删掉「文章专属设置」独立框 + 「文中元素」分组，
  把规则控件（下拉→分段切换）和署名图开关都并入「底部区域」details。

目标形态：
```
▽ 底部区域                          本文显示 [●]
   规则  [ 自动 ][ 默认 ][ Mote 作者 ]   ← 分段切换，始终显示
   参考文献前署名图              [●]     ← Mote 规则下出现且默认开；默认规则下不出现
   提示标题                      [●]
   提示正文                      [●]
   Bobo 名片                     [●]
   更多文章                      [●]
```

设计决策：
- 规则分段控件放 details 内、summary 下、始终显示（它决定整套 profile，含署名图 + block 默认）。
- 署名图开关独立于「本文显示」总开关——因为它渲染在正文，不是文末模块。「本文显示」关闭时
  署名图开关仍在（off-note 文案精确化为「文末模块」）。这是它真实渲染位置决定的，非 bug。
- 「自动」档保留（智能默认：Mote 文章自动套 Mote 规则），当前匹配结果走 tab title 悬停。
- 署名图行复用 block 行视觉（bp-block-item），与提示/名片开关完全一致——统一交互语言。

## 结论

用户的架构批评成立且已修正。这次是**纯 L4 交互层重组**——渲染管线（behavior action 注入正文
署名图）、规则数据（profile 的 artifact_visibility / block_visibility）、复制契约全未动，
零风险。旧的「artifact_visibility 独立于 block_visibility」双机制在数据层仍存在（对用户不可见），
但交互层已统一为「底部区域的模块开关，规则决定默认」。未来若要数据层也彻底统一（把署名图
变成带渲染锚点的 bottom_blocks block），需碰渲染管线 + 复制契约，属更大工程，本次未做。
