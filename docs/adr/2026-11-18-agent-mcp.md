# 智能体入口：MCP + 本项目自己当授权服务器（2026-11-18）

状态：已采用。接法与维护见 [agent-mcp.md](../agent-mcp.md)，规则见 CLAUDE.md 红线 51。

## 背景

用户 2026-11-18：「我们团队成员希望在codex里或者别的智能体里也用上这个排版工具……需要通过mcp授权登录。接我们的飞书登录页面。然后才能用」。范围选 A：智能体排版、校对，给一个链接，人在排版工具编辑器里接着改、复制到后台；不碰任何平台。

## 决定

1. **MCP，照官方授权规范（2026-07-28）**。Codex、Claude Code、Cursor 都按这套规范自己完成登录：读受保护资源元数据（RFC 9728），再读授权服务器元数据（RFC 8414），动态注册（RFC 7591），带 PKCE S256 和 `resource`（RFC 8707）走授权码，之后自己续期。MCP 协议层用官方 Go SDK（`modelcontextprotocol/go-sdk` v1.8.0，含 `auth`、`oauthex`），不自己写协议。
2. **本项目自己当授权服务器，认人走统一登录**（`api/internal/mcpauth`）。统一登录只给登记过的项目发登录会话，不给智能体客户端发 MCP 令牌。所以由本项目发令牌：授权页没登录就跳统一登录页（飞书登录），登了出确认页，点「允许」才发码。令牌代表这个人；每次调用、每次续期都查一遍账号状态和登录中心的停用名单，停用、离职了当场进不来。
3. **只走动态注册，回调只收本机地址**（127.0.0.1、localhost 任意端口，或本机应用协议）。授权码只会落到点「允许」那台电脑上；别人注册个假名字骗人点允许，也拿不到码。不声明客户端元数据文档（CIMD）：声明了，支持 CIMD 的客户端就不再注册，而服务器连不上放文档的那些站，会把这些智能体全挡在外面。
4. **令牌只存哈希**：访问令牌 1 小时；刷新令牌每次换新，旧的留 1 分钟，重复用整份授权作废；30 天不用或满 90 天要重新点允许。授权码重复用整份授权作废。授权记录落盘，重启还在。
5. **排版、校对不另写**。排版和排版接口同一条路（`layoutAPI.launch`），成品与网页「导入→复制」逐字一样（红线 46）。校对和网页「AI 校对」同一个 `articleChecker`，同一篇在编辑器里、智能体里只查一次（红线 49）。
6. **交接是重新导入，不是存成品**。每篇记下交来的那份输入；编辑器打开 `?agent=<编号>` 时按同一份输入、走人自己操作的同一个入口再导一次（链接、文字走粘贴，Markdown、Word 走上传）。之后的预览、校对卡、复制、改稿都是编辑器原来那套，不用为智能体另做一份。记录只给本人看，留 7 天。
7. **飞书文档用这个人自己的飞书授权读**：他读得到的就能排，不用把应用加进文档；他没授权才退回应用身份。
8. **`.md` 在根上修**。智能体多半交 Markdown，接的时候发现公众号模板的 `.md` 导入不认标准写法，会漏出 `##`、`-`、`>`。改成三个模板共用 `parser.js` 的 `markdownFileBlocks` 认结构，人上传 `.md` 也一起变好。

## 没选的

- **每人发一把排版接口钥匙（`flk_`）**：要人手发钥匙、手动停用，也没有飞书登录这一步，不合要求。
- **本机装一个 stdio 服务**：每台电脑要装、要更新，登录照样要做一遍。
- **智能体直接拿成品 HTML 去用**：复制进公众号后台要走编辑器的复制层（图片、存活规则，红线 9/23），智能体做不到。成品 HTML 只在 `include_html` 时给，一般不用。
- **让智能体存草稿或发布**：用户选 A，不碰平台。

## 后果

- 本项目多了一份授权记录（`agent-grants.json`）和交接记录（`agent-results/`）。
- 改排版、校对时智能体自动跟着变，不用另改。
- 登录中心的停用名单读不出来时，智能体和网页登录一样拒绝。
