# FoodTalks 编辑部发布规范（从历史文章倒推）

> 数据来源：阿里云 RDS `mc-fb` 库（只读账号），`news_news` / `news_news_tag` / `basic_tag` 三表。
> 采样窗口：2026-06-10 ~ 2026-07-10 已发布文章（`publish_status=1 AND is_active=1`）共 **163 篇**；标签词表另取近 12 个月。
> 用途：本文件是 AI 预填提示词（`api/editorial/norms_prompt.md`）的**唯一真相源**——规范变更先改这里，再同步 prompt。规范与模型解耦：prompt 只含声明式规则 + 真实范例，不依赖任何特定模型的特性，换模型时只需重跑评测（见 §7）。

## 1. 转载 / 原创判定（source_type）

**这是确定性规则，由代码判定，不交给模型**（规则五：能用代码就不用模型）。

- `source_type=0`（原创/自有）：文章来自自家账号。近一月数据：FBIF食品饮料创新 63 篇、FoodTalks、FBIF食品创新展、FBIF食品饮料创新论坛。
- `source_type=1`（转载）：来自外部媒体。近一月：零售圈、联商网、小食代、咖门、蓝鲸新闻、红餐网、顶尖广告……
- 判定：`source_name ∈ 自家账号清单` → 0，否则 → 1。自家清单默认 `FBIF食品饮料创新, FBIF食品饮料创新论坛, FoodTalks, FBIF食品创新展`，env `SITE_OWN_ACCOUNTS` 可覆盖。
- **例外（模型唯一参与点）**：自家公众号转发别人的文章时，正文头部会有出处声明（「本文来自微信公众号：小食代」「本文为新零售原创，作者：陈新生，转载请联系出处」「来源：联商网」）。模型负责**抽取**这个声明出处 → 有且不是自家账号 → source_type=1 且 source_name=声明出处。
- 分布佐证：163 篇中 0:1 = 93:70（含个别历史脏数据如 source_type=0 的「零售圈」2 篇，不作依据）。

**163/163 篇全部填写来源名**（4 篇为空串属脏数据）。原创=自家账号名；转载=原出处媒体名。

## 3. 摘要（summary）——用户点名整改项

**编辑部摘要不是内容概括，是一句话钩子。**

| 指标 | 值 |
|---|---|
| 平均长度 | **29 字** |
| ≤30 字占比 | 70% |
| ≤40 字占比 | 84% |
| ≤60 字占比 | 94% |
| 结尾标点 | 句号 114 / 问号 26 / 叹号 8 |

四种真实写法（全部来自库内真实样本）：

1. **提问式悬念**：「IP联名的底层逻辑是什么？」「为什么真露能够连续25年成为全球最畅销蒸馏酒？」
2. **断言式金句**：「又一食品品类王上市。」「泰式奶茶，中式打法。」「不追求爆品，追求高频。」
3. **数据点睛**：「17岁高中生买下的小店，要去纽交所上市。」「水和饮料单品销售额在名单中表现最好，占据名单中62个单品。」
4. **原文引语**：「"生鲜市场体量有多大，新鲜方便菜的天花板就有多高。"」

规则化：10~40 字一句话；禁「本文/文章/这篇」开头与「介绍了/分析了/探讨了」总结腔；句号/问号/叹号结尾；允许复用标题片段（编辑部真实惯例，如 62384）。
（旧 prompt 写死「80-120 字摘要」——比编辑部 p94 分位还长，即用户 2026-07-10 反馈「摘要有点太长了」的根因。）

## 4. 标签（tags）

- **每篇 1~3 个**：1 个 64 篇 / 2 个 48 篇 / 3 个 18 篇 / 0 个 28 篇；4 个仅 5 篇。
- **粒度只有三类**：品牌·公司名（喜茶、赛百味、三得利）/ 行业品类词（饮料、零食、便利店、茶饮）/ 栏目·活动名（FBIF2026会后报告、创新周报——栏目标签由编辑手工体系管理，AI 不打）。
- **不存在抽象概念标签**：「热点营销」「品牌破圈」「消费升级」这类词近一月 0 次出现（此前 AI 输出这类词=跑偏）。
- **标签是封闭词表选择，不是自由生成**：`news_news_tag` 每行 `{tag_id, tag_name}` 关联 `basic_tag`（新闻标签 `tag_type_id=6`，全库 7.7 万个，近一年实际用过 2063 个、≥5 次的 235 个）。高频词表已导出 `api/editorial/tag_vocab.json`（近一年 cnt≥2 前 500，含 tag_id）；prompt 注入前 300 个名字，主角品牌不在词表时允许直接用品牌名。
- **newsTags API 结构已实锤**（2026-07-10 测试环境实验）：要对象数组 `[{tagId, tagName}]` 且 tagId 必须真实存在（POST 成功）；但后端 PUT 路径有 bug（带标签必 500 且污染文章），修复前流水线 newsTags 恒空、标签只做展示——完整矩阵见 `docs/foodtalks-api-contract.md` §9。

## 5. 作者（author）

- **132/163 为空**——作者不是必填项，宁空勿造。
- 填写时机：有明确**个人**署名（Mote、何丹琳、李达、李娜Linda）；机构名偶用（FoodTalks、纽锐拓消费者指数）。
- 反例佐证：62523 正文头部明写「作者：陈新生」但编辑部 author 留空——说明编辑部对转载文作者填写是宽松裁量。因此预填策略：**模型照抄正文署名给审核人参考，绝不编造**（此前 AI 输出「热点事件洞察部」即幻觉编造，违规）。
- **结构化直取优先（2026-07-10 用户裁定「从公众号里直接提取更准」）**：公众号文章页有发布者自己填的结构化作者字段（`<meta name="author">` / `var author = "..."`，公众号名在 `var nickname = htmlDecode("...")`）——fetching 阶段确定性直取（`extractWechatArticleMeta`），**AI 只在页面未署名时兜底**。此修正同时补上了 fetching 一直漏抓公众号名的暗伤（生产 job #1/#2 source_name 为空）。
- 流水线口径（2026-07-10 修订）：author=结构化署名 → AI 兜底（可为空），**不再回落 source_name**——来源信息由 source_name 字段承载，塞进 author 是字段错位。

## 7. 准确率评测（换模型的回归门）

- 评测集：`tools/enrich-eval/eval_set.json`——近一月 40 篇真实文章（30 篇最新 + 10 篇有署名；25 原创/15 转载），输入=标题+正文 HTML，期望=编辑部实际 summary/tags/author/source_name。
- 评测器：`api/publish_enrich_eval_test.go`，`ENRICH_EVAL=1 ARK_API_KEY=... go test -run TestEnrichEval -v -timeout 30m` 真调 ARK，走与生产逐字节相同的 `arkEnrichArticle` 链路。
- 指标与达标线：摘要长度合规（5~45 字）≥90%、摘要风格合规（无禁用开头、单句）≥90%、标签数量合规（1~3）≥95%、作者精确率 ≥80%（仅对编辑部有填的样本；匹配用「一方包含另一方」——编辑部对同一人有 Mote莫特/Mote/mote 三种写法，AI 照抄正文原署名不算错）、出处抽取（转载样本）≥70%、作者幻觉编造 =0（红线）。
- 标签命中率仅报告不做门禁（2026-07-10 后端裁定标签走单独接口、发布先不标注，契约 §9；且编辑部真值混有「FBIF2026会后报告」等人工栏目标签，AI 按规范不产出）。标签接口接入时回升为门禁。
- 换模型流程：改 `ARK_MODEL_ID` env → 重跑评测 → 全部达标即可切，prompt 不用动（声明式规范+范例，无模型特定语法）。

## 8. 数据再生（规范演化时重跑）

```sql
-- 词表（近 12 个月，cnt≥2 前 500）
SELECT JSON_OBJECT('tag_id',t.tag_id,'tag_name',t.tag_name,'cnt',COUNT(*))
FROM news_news_tag t JOIN news_news n ON n.id=t.news_id
WHERE n.publish_time >= DATE_SUB(CURDATE(), INTERVAL 12 MONTH) AND n.publish_status=1 AND n.is_active=1
GROUP BY t.tag_id,t.tag_name HAVING COUNT(*)>=2 ORDER BY COUNT(*) DESC, t.tag_id LIMIT 500;

-- 评测集（近 1 个月 30 篇 + 有署名 10 篇，排除「确认参展」模板文）
-- 见 WORKLOG-publish-pipeline-in-layout-2026-07-10.md M7 节的完整导出命令
```
